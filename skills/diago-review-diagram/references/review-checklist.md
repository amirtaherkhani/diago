# Diagram review checklist

## Correctness

- Trace every important node and edge to evidence.
- Confirm direction, protocol, sync or async behavior, and ownership.
- Confirm the diagram matches the named environment, branch, and version.
- Flag claims that are only implied by naming or directory structure.

## Decision usefulness

- Restate the decision this view supports.
- Remove detail that does not change that decision.
- Add missing failure, trust, state, or data boundaries.
- Separate current behavior from a proposed target state.

## Readability

- Keep one primary reading direction.
- Prefer short verb phrases on edges.
- Use grouping only for real boundaries.
- Check 360 px, 768 px, and 1440 px widths.
- Check keyboard navigation, focus, contrast, and reduced motion.

## Review response

For every finding include severity, evidence, impact, and a concrete correction. End with a short acceptance summary and unresolved questions.
