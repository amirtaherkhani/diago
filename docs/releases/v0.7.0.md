# v0.7.0

## Highlights

Diago v0.7.0 adds evidence workflow planning to the CLI and MCP server. Diagram authors can plan independent inspections, wait for dependent checks, and keep failed or conflicting reports visible. The release also includes the navy and yellow identity, a refreshed README, and a public setup guide.

## Added

- `diago evidence <workflow.json> [--json]` and the read-only `plan_evidence_workflow` MCP tool.
- A versioned workflow snapshot schema and checkout example with parallel API/storage inspections followed by contract verification.
- Ready-task selection respecting concurrency limits, dependency failures, reported elapsed time, and attempt budgets.
- Plan-compatible evidence with preserved citations and explicit conflicting, rejected, and unverified claim reports.
- A public getting-started guide and FAQ covering installation, local operation, diagram outputs, and release availability.

## Changed

- Applied the yellow interlocking D logo and midnight-blue palette to the plugin, repository, website, and sharing previews.
- Reworked the README with expandable setup instructions, prompt examples, and contribution guidance.
- Added search and sharing metadata, linked structured data, a two-page sitemap, and maintainer guidance for discovery and community participation.
- Replaced the header's GitHub button with an accessible icon and added X, Hashnode, and DEV logo links beside the footer navigation.

## Fixed

- Automatic diagram-preview transitions and motion-preference changes no longer scroll readers away from lower sections of the homepage.

## Migration

- Update an older plugin installation to v0.7.0 to use `plan_evidence_workflow`. The release includes eight diagram views and seven MCP tools.
- Existing diagram plans and renderer inputs remain compatible. The new evidence workflow snapshot uses its own schema version 1.

## Configuration

- Defaults: three concurrent tasks, two total attempts per node, and 15 seconds per attempt. The workflow supports up to 32 nodes.
- The host owns source inspection, verification, worker cancellation, and snapshot persistence. Mark tasks running before dispatch and stop timed-out work before retrying.
- CLI status is 0 for pending or complete work, 1 for terminal incomplete work, and 2 for invalid input. Check the report's `status` and `ok` before consuming evidence.
